Privacy policy

DevSec Toolkit collects no personal data. Last updated: October 15, 2026.

The short version

DevSec Toolkit works entirely inside your browser. We do not collect, store on a server, sell, or share any information about you or the websites you visit. There are no accounts, no analytics, no advertising and no remote code.

What the extension reads

  • The page you scan. When you press "Scan this page", the extension reads that page's HTML, scripts, headers, and browser storage so it can show findings. It does this only for the active tab and only after you click.
  • Cookies (optional). If you press "Check cookies", Chrome asks for permission for that one site. Cookie attributes are analyzed locally and never leave your device. You can remove the permission at any time.
  • Proxy settings (optional). If you press "Use Burp" on the Burp tab, Chrome asks for permission to change this browser’s proxy. Host and port you enter are stored locally. Traffic is sent to the proxy you choose (typically Burp on your machine), not to us.
  • Network requests (optional). If you press "Start monitoring" on the Network tab, Chrome asks for permission to observe http(s) request metadata (URLs, methods, status codes, headers, timing). This stays in memory on your device for the recent buffer and is never uploaded. Full request/response bodies are not read.

What is saved on your device

Findings you add to a report, the report title, author and scope you type, your Burp proxy host/port preference, and whether network monitoring is enabled are stored with chrome.storage.local on your computer so they are there next time. Recent network rows are kept only in memory while the service worker is alive. Use "Clear all" on the Report tab, stop monitoring / disable the Burp proxy, or remove the extension, to delete them. Nothing is synced or uploaded.

Network activity

A scan makes requests only to the website you are on (its own page and its own script files) to read headers and look for exposed secrets. The extension never sends data to us or to any third party. If you enable the Burp proxy, your browser’s web traffic is routed through the proxy listener you configured (for example Burp Suite on localhost). If you enable Network monitoring, request metadata is observed locally via Chrome’s webRequest API for tabs you browse while it is on.

Permissions, in plain language

  • activeTab, tabs, and scripting: find the page in your main browser tab and run a scan when you click. The side panel stays open, so the extension needs to read the active tab’s address locally.
  • storage: remember your report, Burp proxy, and network-monitoring preferences on your device.
  • sidePanel: show the toolkit beside the page instead of a popup.
  • cookies (optional): check cookie flags for a site you approve.
  • proxy (optional): set or clear Chrome’s proxy so traffic can go through Burp Suite when you toggle it.
  • webRequest (optional): observe request metadata for the Network console when you start monitoring.
  • Host access for http(s) sites (optional): needed to see network requests across sites you visit while monitoring, or for a single origin if a scan needs it after the side panel was already open.

Children

The extension is a developer tool and collects no data from anyone, including children.
